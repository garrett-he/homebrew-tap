# Formula Anatomy

A formula is a Ruby class inheriting from `Formula`. Keep it lean and declarative.

## Minimal skeleton

```ruby
class Foo < Formula
  desc "One-line description of what the formula does"
  homepage "https://www.example.com"
  url "https://example.com/foo-1.2.3.tar.gz"
  sha256 "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  license "MIT"

  depends_on "pkgconf" => :build

  def install
    system "./configure", *std_configure_args
    system "make", "install"
  end

  test do
    assert_match "foo 1.2.3", shell_output("#{bin}/foo --version")
  end
end
```

Note: a purely version-output test is only acceptable as a last resort. Prefer a functional test.

## Required and common stanzas

| Stanza | Purpose / rule |
|---|---|
| `desc` | One line. The formula name is prepended automatically, so do not repeat it. |
| `homepage` | HTTPS URL, required. If it blocks bots but works in a browser, add `browsed: "YYYY-MM-DD"` with a real past date. |
| `url` | Immutable, versioned source archive. |
| `sha256` | Checksum of the exact archive at `url`. |
| `version` | Add only when brew cannot derive it from the URL. |
| `license` | SPDX identifier, e.g. `"MIT"`, `"BSD-2-Clause"`, `"Apache-2.0"`. Use `license :public_domain` for public domain. Dual/mixed licensing uses `any_of:` / `all_of:` forms. |
| `depends_on` | Formula or requirement dependencies; see below. |
| `uses_from_macos` | Prefer the macOS-provided version of a library on macOS, a formula elsewhere. |
| `def install` | Build and install logic; starts in the extracted archive directory. |
| `test do` | Functional check run by `brew test` and BrewTestBot. Starts in a temporary `testpath` with `HOME` set to it. |
| `head` | Optional bleeding-edge source, e.g. `head "https://github.com/user/foo.git", branch: "main"`. |
| `revision` | Integer; bump to rebuild the same source archive without changing the version. |
| `keg_only "reason"` | Keep the formula unlinked, e.g. when it duplicates a macOS library or is a dependency-only runtime. |
| `resource "name" do ... end` | Extra checksummed downloads, including test-only resources declared outside `test do`. |
| `caveats do ... end` | Post-install notices shown to users. |
| `service do ... end` | launchd service definition. |
| `bottle do ... end` | Generated by brew; do not hand-write. |

## Dependency syntax

```ruby
depends_on "jpeg"                          # normal formula dependency
depends_on "pkgconf" => :build             # needed only while building
depends_on "httpd" => [:build, :test]      # build and test only
depends_on "readline" => :recommended      # not allowed in homebrew/core
depends_on "gtk+" => :optional             # not allowed in homebrew/core
depends_on xcode: ["9.3", :build]          # requirement with metadata
depends_on arch: :x86_64                   # architecture constraint
depends_on macos: :sonoma                  # minimum macOS version

uses_from_macos "bzip2"
uses_from_macos "perl" => [:build, :test]
uses_from_macos "curl", since: :monterey
```

Use `=> :no_linkage` when the formula does not link against a declared dependency. Prefer `uses_from_macos` for libraries Apple ships (zlib, bzip2, libxml2, curl, ruby, perl).

## Language resources

For language package managers, use checksummed `resource` blocks instead of relying on the contributor's global environment:

```ruby
resource "example" do
  url "https://registry.example.com/example-1.0.0.tar.gz"
  sha256 "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
end
```

Test-only resources live outside `test do` with `:test` metadata:

```ruby
resource "testdata", :test do
  url "https://example.com/input.foo"
  sha256 "ffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff"
end

test do
  resource("testdata").stage do
    assert_match "OK", shell_output("#{bin}/foo build-foo input.foo")
  end
end
```

Fetch them ahead of an offline install with `brew fetch --test <formula>`.

## Writing `test do`

- Require no user input and avoid network access.
- Exercise real functionality, not only `--version` or `--help`.
- Use `shell_output`, `assert_match`, `assert_equal`, and `assert_path_exists`.
- Capture stderr with `shell_output("#{bin}/foo 2>&1", status)` when output goes there.
- Assert exit status when the command is expected to fail: `shell_output("#{bin}/foo bad", 1)`.

## Post-install steps

```ruby
post_install_steps do
  mkdir_p "log/foo", base: :var
  touch "foo/state", base: :var
  move "default.conf", "foo/default.conf"
  symlink "cert.pem", "foo/cert.pem", source_base: :relative
end
```

Do not define a `post_install` method; new methods are rejected.
